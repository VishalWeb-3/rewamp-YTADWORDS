# Tina CMS admin setup

## Fix "Branch 'main' not found" (after you've already committed)

Tina Cloud needs **both** the `tina` folder and **`tina-lock.json`** to index your branch. If you committed but the admin still says "Branch 'main' not found", do this:

1. **Ensure `tina-lock.json` exists** in `frontend/tina/`. If it's missing, run:
   ```bash
   npm run build:admin
   ```
   Then check that `frontend/tina/tina-lock.json` exists (it's created from the generated schema). If it wasn't created by the build, it may have been generated by the script in this repo.

2. **In Tina Cloud** → your project → **Configuration**:
   - **Path to Tina Config**: must point to where the `tina` folder lives in your repo.
     - If your repo root has a `frontend` folder and the tina folder is `frontend/tina/`, use **`frontend`** (Tina will look for `frontend/tina/config.js`).
     - If that doesn't work, use **`frontend`** only (do not use `frontend/tina`).
   - Click **Refresh Branches** and wait a few minutes. `main` should then appear.

3. **Commit and push** the full `tina` folder (including `tina-lock.json` and `__generated__/`). If "No branches found" appeared because `tina-lock.json` was never pushed, add and push it:
   ```bash
   git add frontend/tina/tina-lock.json   # or: git add frontend/tina/
   git status   # confirm tina-lock.json is included
   git commit -m "Add tina-lock.json for Tina Cloud indexing"
   git push origin main
   ```

4. **Refresh Branches** again in Tina Cloud (Configuration → Refresh Branches). Wait a few minutes, then reload [http://localhost:5173/admin/index.html](http://localhost:5173/admin/index.html).

## Fix "GraphQL Schema Mismatch" / "Schema is not configured" (after adding pricing or any new collection)

This means the schema on **GitHub** (what Tina Cloud uses) is older than your local schema. Push the new schema and reindex:

1. **Commit and push the full Tina schema and pricing content** (from repo root):
   ```bash
   cd frontend && npm run build:admin && cd ..
   git add frontend/tina/
   git add frontend/content/pricing/
   git add frontend/public/admin/index.html
   git add frontend/src/contexts/ContentContext.jsx
   git add frontend/src/pages/Buy*.jsx
   git status
   git commit -m "Add All Details Pricing collection and dynamic prices"
   git push origin main
   ```
   If you're already in `frontend/`, use paths without `frontend/` (e.g. `git add tina/ content/pricing/`).

2. **Tina Cloud Configuration**:
   - Set **Path to Tina Config** to **`frontend`** (so Tina finds `frontend/tina/config.js`).
   - Click **Refresh Branches**, then find **main** and click **Reindex** (not just Refresh). Wait 3–5 minutes.

3. **Tina Cloud Overview** (not Configuration):
   - Open the **Project Setup Checklist** and complete any steps (e.g. “Push your schema”, “Run first build”) so the warning “Branches will not be indexed until your schema is configured” goes away.

4. **Hard-refresh the admin**: [http://localhost:5173/admin/index.html](http://localhost:5173/admin/index.html) (Cmd+Shift+R) or open in an incognito window.

If you added a new collection (e.g. Pricing), the mismatch and “schema not configured” persist until `tina-lock.json` and the full `tina/` folder are pushed and the branch is **Reindexed**.

## Get the admin to open (first time)

1. **Build the admin**: `npm run build:admin` (generates `public/admin/` and `tina/__generated__/`).
2. **Commit and push** `frontend/tina/` (including `tina-lock.json`).
3. **Tina Cloud** → Configuration: set **Path to Tina Config** (e.g. `frontend`), then **Refresh Branches**. Add **Site URLs** (e.g. `http://localhost:5173`).
4. Run `npm run dev` and open [http://localhost:5173/admin](http://localhost:5173/admin).

## Env vars (in `frontend/.env`)

- `TINA_CLIENT_ID` or `Tins_client` – from Tina Cloud project
- `TINA_TOKEN` or `Tina_token` – from Tina Cloud project  
- `TINA_BRANCH` (optional) – default is `main`

## Scripts

- `npm run build:admin` – builds the admin (skips cloud branch check so it works before indexing).
- `npm run build:admin:local` – same as above (explicit name).

Once your branch is indexed in Tina Cloud, you can remove `--skip-cloud-checks` from the script in `package.json` if you want the build to verify the branch in CI.
